The existing helper's lack of locking/unique doc_no remains a separate all-writer migration concern; this helper alone does not fix its concurrency.

## Required guarded command boundary

Use a separate restricted legacy DB principal with EXECUTE on controlled SQL SECURITY DEFINER command(s), SELECT only where necessary, and **no direct DML on protected headers, active-master, member deduction configuration, reservation, immutable snapshot, or proof state**. Public create principal likewise cannot execute the legacy processing command. Session variables and caller-supplied `origin=PUBLIC`/`is_mobile` are not authorization capabilities.

The controlled command owns the entire transaction and cannot be nested inside unrelated writes: authenticate permitted controller/actor/action; acquire canonical member lock and shared reservation in the same ordering as every create/edit/cancel/process writer; lock and re-read unique header/member/active-master facts; validate OPEN state, exact member identity, current section and intended savings type, immutable snapshot, proof READY (PRIVATE signature and exact frozen PDF hash), and allowed transition **before the first effect**. Duplicate active-master rows must fail closed. APPROVED updates/inserts active configuration, updates `m_anggota.sim_sukarela`, then changes header status in the same transaction; REJECTED changes only the header and releases the reservation according to B-05. APPROVED keeps reservation until independently confirmed posting. Explicit required insert fields prevent dependence on permissive SQL mode. Any SQL error, affected-row mismatch or connection failure rolls back the command. Do not replay an unknown commit without an idempotency receipt lookup.

A final-header trigger is only defense in depth: unmodified CI2 autocommit performs master and member effects *before* the header write, so rejecting that last write leaves earlier commits. Existing CI2 must call the controlled command or acquire an explicit whole-command transaction with equivalent denied direct-write privileges. Keep approval authority with CI2; the public Next application must not receive this capability. Laravel MOBILE create/edit/cancel and the second CI2 simpanan variant must use guarded commands or be denied protected writes, including direct API paths. Known PUBLIC doc_no is not permission to modify it.

## Executable local fixture delivered

`../schema.sql` is a disposable **replacement fixture schema**, with representative legacy columns plus deliberate unique NIK/doc_no/active-master constraints and auxiliary controls. It must not be applied to an existing database as a migration. `../staging.mjs setup` creates or starts only the labeled `kkisi-public-savings-integration` container on `127.0.0.1:3318`, MariaDB 11.4. It creates random dedicated accounts/config without reading `.env`. Config/admin files are ignored and mode0600; directory mode0700. Every exported connection checks the installation sentinel. Existing unknown installations fail closed. `reset` verifies the sentinel before recreating only this disposable schema; it leaves other containers/databases/volumes alone. `seed` is idempotent. Root credentials are kept in a separate admin file; public runtime config has no admin credential.

Local `pss_legacy_transition(reference, action, actor)` is the whole-command fixture boundary; actions APPROVE, REJECT, CANCEL. It owns its transaction, locks the shared member-control then header/member rows, applies maker-checker and READY proof checks before writes, performs active-master/member/header atomically, and rolls back every effect on failure. APPROVE maps to legacy APPROVED and keeps the B-05 reservation. REJECT/CANCEL map to verified legacy REJECTED, with distinct durable audit events and reservation release; a production CANCELLED mapping still requires verified legacy-owner policy. The public role has no EXECUTE grant. Legacy executor has no direct DML grants. `pss_command_guard` is a protected definer-written table keyed by connection, never a caller-controlled session variable. Header guards reject even privileged accidental direct updates. Only definer commands can write headers; deletes are refused.

`pss_mobile_create(member_id, reference, amount, month, year, actor)` and `pss_mobile_mutate(reference, EDIT|CANCEL, amount, actor)` are explicitly source-equivalent local fixtures for the Laravel writer contract. They serialize on the same member-control row and deny PUBLIC mutations. They do not emulate Laravel profile-signature writes, email/provider calls, HTTP authentication, framework response behavior, or an actual CI2 menu. Actual PHP must call equivalent controlled commands with actor bound to the authenticated session; a caller-provided actor string in a SQL fixture is **not** evidence of real menu authorization or maker-checker identity binding.
