# 12 — Financial Reconciliation & Data Contract Validation (WS-04)

## 1. Source-to-Screen Reconciliation Matrix

Every financial figure in `apps/mobile_kkisi` is computed by the exact same `@koperasi/domain/kosipa` and `@koperasi/application/kosipa` rules used by the KOSIPA console (`apps/web`). Floating-point arithmetic is never used: SQL casts all `DOUBLE` and `DECIMAL` columns to exact `DECIMAL(24,2)` or `DECIMAL(24,4)` strings (`dec()`), and domain services compute in integer `amount4` ($\text{Rp} \times 10{,}000$) or integer `sen` ($\text{Rp} \times 100$).

| Domain & Screen | Legacy Tables & Columns | Domain / App Rule | Status & Filter Rules | Anomaly & Edge-Case Handling |
|---|---|---|---|---|
| **Savings Summary**<br>`/beranda`, `/simpanan` | `trans_simpanan_dtl` (`kredit`, `kredit_cash`, `debit`, `jasa_kredit`, `jenis_simpanan`, `doc_status`)<br>`trans_simpanan` (`doc_no`, `doc_status`, `jenis_simpanan`) | `summarizeTypes()` in `@koperasi/domain/kosipa` + `buildSavingsSummary()` | Only rows whose single matching header has `doc_status = 'APPROVED'` are summed into `recorded4` ($\text{kredit} + \text{kredit\_cash} + \text{jasa\_kredit} - \text{debit}$). `OPEN`/`POSTING` go to `pending4`. | Labelled *"Total Simpanan Tercatat"* (never "official balance", as `m_anggota.sim_*` is unverified). Missing (`MISSING_HEADER`) or duplicate (`AMBIGUOUS`) headers are excluded from `recorded4` and set `hasUnverified = true`, rendering a warning banner. |
| **Savings Movements**<br>`/simpanan` (Setoran / Penarikan) | `trans_simpanan_dtl` + `trans_simpanan` (`doc_date`, `jenis_transaksi`) | `describeMovement()` + `buildMovements()` | Keyset-paginated (`id < beforeId`). Categorized as `POSTED` (`APPROVED`), `PENDING` (`OPEN`/`POSTING`), `VOID` (`REJECTED`/`CANCEL`), or `UNVERIFIED`. | `0000-00-00` or out-of-range dates (`< 1990` or `> 2100`) are classified by `classifyLegacyDate()` and rendered as *"Tanggal tidak tercatat"*. |
| **Active Deductions & Requests**<br>`/simpanan?tab=potongan`, `/potongan/ajukan` | `m_simpanan_aktif` (`potongan_payroll`, `status`, `periode_start`)<br>`trans_simpanan_pengajuan` (`potongan_old`, `potongan`, `doc_status`) | `buildActiveDeductions()` & `validateDeductionChange()` | Latest row per `jenis_simpanan` with `status = 1`. Zero deductions (`0.00`) are kept as recorded values. | `SIMPANAN WAJIB` may only increase (`value > current`); `SIMPANAN SUKARELA` may increase or decrease (`value !== current`). Whole Rupiah only. |
| **Active Loan & Schedule**<br>`/beranda`, `/pinjaman` | `trans_pinjaman` (`plan_pinjaman`, `plan_angsuran`, `plan_jangka_waktu`, `doc_status`, `status_pencairan`, `status_bayar`)<br>`trans_pinjaman_dtl` (`ke_cicilan`, `tgl_cicilan`, `pokok_cicilan`, `bunga_cicilan`, `angsuran_cicilan`, `status_cicilan`) | `describeLoan()`, `assessSchedule()`, `describeScheduleRow()`, `buildActiveLoan()` | Active loan = `doc_status = 'APPROVED' AND status_pencairan = 'APPROVED' AND status_bayar <> 'LUNAS'`. Remaining principal & total are summed from `status_cicilan = 'Belum Bayar'` rows. | `actual_*` header columns are ignored (0 on 100% of legacy rows). Schedule anomalies (`ROW_COUNT_DIFFERS_FROM_PLAN_MONTHS`, `PRINCIPAL_SUM_DIFFERS_FROM_PLAN`, `DUE_DATES_UNUSABLE`, `ROW_TOTAL_DIFFERS_FROM_PRINCIPAL_PLUS_INTEREST`) are surfaced in `scheduleIssues` and shown in a warning note. |
| **Loan Simulation**<br>`/pinjaman/ajukan` | `m_pinjaman_mobile` (`min_nominal`, `max_nominal`, `min_jw`, `max_jw`, `jasa`, `status = 1`) + `m_jenis_pinjaman` (`jenis_bunga`) | `loanSchedule()` in `@koperasi/domain/kosipa` + `simulateLoan()` | Enforces product `minSen..maxSen` and `minMonths..maxMonths`. Supports both `Flat` and `Anuitas` methods. | If `jasa` rate or `m_jenis_pinjaman` method is missing/non-numeric, simulation refuses with `field: 'rate'` (never guesses a default rate). |
| **Payroll Deductions**<br>`/beranda`, `/potongan` | `trans_potongan_matrix` (47 component columns + `total_potongan`, `potongan_toko`)<br>`trans_potongan_bulanan` (`doc_no`, `doc_status`, `periode_th`, `periode_bl`) | `summarizeMemberPayroll()` (`@koperasi/application`) + `describeRow()` (`@koperasi/domain`) + `buildDeductionPeriods()` | Reads all 47 `DECIMAL(18,4)` component columns at 4-decimal precision (`amount4`). Header status `APPROVED` -> *Selesai*, `OPEN` -> *Dalam proses*. | Recorded `total_potongan` is displayed as-is; if $\sum \text{components} \neq \text{total\_potongan}$, `totalMatches = false` displays an explicit warning note rather than silently altering the total. |
| **SHU**<br>`/beranda`, `/shu` | `trans_shu` (`doc_no`, `publish = 1`)<br>`trans_shu_dtl` (`periode_th`, 7 SHU value columns) | `readShu()` + `buildShuYears()` | Strictly filters `trans_shu.publish = 1`. Deduplicates by `periode_th` newest-first. | Unpublished years (`publish = 0`) are never exposed to members. All 7 recorded columns (`jasa_simpanan`, `jasa_transaksi_usaha`, `total_shu`, `total_shu_pembulatan`, `jasa_simpanan_sukarela`, `pembulatan_sukarela`, `pendapatan_shu`) are shown verbatim without recalculation. |
| **Store Credit**<br>`/beranda`, `/saldo`, `/belanja/checkout` | `m_anggota` (`status_anggota`, `status_karyawan`, `tgl_keluar`, `limit_toko`, `gaji_minus`)<br>`db_sales` (`payment_type = 'Kredit'`, `sales_status = 'Final'`, `sales_date`)<br>`db_salesreturn` (`grand_total`) | `evaluateStoreCredit()` (`@koperasi/domain`) + `buildStoreCredit()` | Window = current Jakarta (`Asia/Jakarta`) calendar month `[start, endExclusive)`. $\text{usedSen} = \max(0, \text{spentSen} - \text{returnedSen})$. | Matches POS cashier rule: if `gaji_minus > 0`, ceiling is `gaji_minus`; otherwise `limit_toko`. Non-`AKTIVE` members or `KONTRAK` members with `tgl_keluar <= today` are marked `eligible = false`. |
| **Catalog & Cart Pricing**<br>`/belanja`, `/belanja/checkout`, `/api/belanja/harga` | `db_items` (`company_id = 1`, `status = 1`, `status_so = 0`, `type = 'Produk Jadi'`, `custom_barcode <> 'SALDOPPOB'`, `sales_price`) | `readCatalog()`, `readCatalogItems()`, `priceCart()` | Excludes internal `SALDOPPOB` item, inactive items, stock-opname items, and other branches. | Checkout re-queries live prices from `/api/belanja/harga`; zero-priced (`sales_price <= 0`) or removed items are flagged as unavailable and block checkout. |
