# Evidence intake runbook (checkpoint 15)

Purpose: when an operator or the owner delivers evidence, engineering validates it **the same day** with the commands below and unlocks only what the report allows. Every tool here is **offline** (files in, report out): none connects to a database, executes a view or procedure, or needs a credential. Raw evidence stays outside the repository (`docs/migration/_baseline/` is gitignored); only the generated **reports** (identifiers, statuses, counts) may be committed.

## Same-day procedure

1. Put the raw file in `docs/migration/_baseline/` (gitignored). Never paste its contents into a ticket or chat.
2. Run the validator; read the exit code (0 ok, 2 ok-but-not-eligible, 1 unusable).
3. Commit **only** the generated report and update `kosipa-evidence-gate-report.md` / `operator-evidence-acceptance.md` with the status.
4. Open exactly the tasks the report names (see `owner-operator-action-package.md` §5). Anything the report keeps BLOCKED stays blocked.
5. If the evidence changes a decision input (D5 from the procedure body, R1 from role ids, B5 from capacity), record it in `decision-register.md` as **evidence available — awaiting owner decision**; never as approved.
